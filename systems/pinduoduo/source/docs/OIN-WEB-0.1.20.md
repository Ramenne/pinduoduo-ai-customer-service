# OIN Web 0.1.20：消息、上下文、人工贡献的整链整改

基线：0.1.19运行b49c2fc，发布记录9107600。用户要求原OIN源码整链对照后继续整改，不再止于检查或零散发布。本轮复用原聊天库、控制行、发送账和知识候选，不新建平行机制。

## 对照发现的12项整改

1. 自动入口先按真实平台消息ID和对话顺序判断当前/已答/已被后续来话替代。已答旧任务只归档；未可靠落库或读取失败保留接续，不误判为旧消息完成。
2. AI、关键词、默认及商品卡片发送均携带固定对话边界，在原发送登记事务检查；提交前对话更新是尚未发送的旧决定，不标作发送不明或伪造回执。
3. 入站使用平台时刻，接收时间另存created_at。无效或未知平台时间保持空，不把接收时刻冒充平台时刻；展示和本地排序可使用created_at回退。
4. 业务问题保留原始与后续消息来源。旧记录只按仍保存的真实轮次恢复已知来源，不编造已丢证据。
5. 商品/订单卡片和历史消息共用固定边界，不能从全历史另取后来商品混入本轮。
6. 自动和人工入口共用历史格式，保留原卡片ID、规格、订单字段，而不是只给摘要标题。
7. 必需商品/订单内容读取或解析失败时停止准备，保留原输入，不当成没有背景继续答。
8. 人工批次结束保留内部原文；下一批归档旧批次并可回读/显示“历史协作”。历史发送要求不能获得新批次授权。
9. 人工事实保留确认时间。temporary只作为当日人工临时确认；跨日或旧记录无确认时刻进入historical_facts，不再作为当前库存依据。长期/session事实不套同一时限，历史事实仍可被明确纠正替代。
10. 内部纯事实、理解纠正或建议允许issues为空；对客正文仍必须有对应动作，不能借此绕过发送权限。
11. AI未成功分析的自然语言人工来源，在结束批次时进入原候选提炼资料；纯操作确认不入库。未分类来源交给原提炼器理解，但只有符合知识分类且有真实来源的结果可进入待审核候选，不直接发布。
12. 人工直发已accepted的正文可以作为人工贡献提炼候选，不等待额外回显；原发送状态仍保持accepted。dispatching/uncertain/review继续等待核对，绝不伪造confirmed。
