# OIN Web 0.1.18：客服 Harness 业务编排

基线：0.1.17 / e8588a7。需求基线：`HARNESS-IMPLEMENTATION-20261023.md`及用户提供的2026-10-23讨论稿。本版为该讨论的业务链实现，不重做平台收发、知识库或服务框架。

## 实际改动

- 自动对客、AI协作、草稿入口共用`harness_contract`与程序必带的`harness_policy`。模型同一轮输出逐问题动作、必要缺口、简短依据和人工事实，不增加额外分类调用。
- 顾客/工作人员来源、控制代际和历史边界均进入业务上下文。工作人员仍用自然语言输入，删除界面上的事实/指令分类选择；旧客户端入口兼容。
- 现有`pdd_conversation_control`增加可空`harness_json MEDIUMTEXT`。逐问题维护待判断/待顾客/待工作人员/就绪/已回复/已解决，保留对象、来源、关联追问；一个问题结束不关闭其他问题，跨人工批次保留未完成问题。
- 人工事实带原文来源、操作者、适用对象/范围、临时/会话/长期类型及替代关系。未知商品ID的“这款”绑定原问题，不能推成全店事实；不同商品/规格不覆盖旧对象。
- 当前工作人员明确发送仍经过原草稿、权限、代际、历史边界、唯一效果账；混合事实+明确发送可识别，否定/条件/引语不授权。“已处理/不要发”有程序否决，不生成虚假平台成功记录。
- 自动处理可先答有依据的问题，再通过原持久接管把其他问题交工作人员。发送结果与问题状态分开；仅平台已接受/确认才记对应问题已回复，旧回执不覆盖新一轮问题。恢复只读原本地发送账，不新增平台请求或重发队列。
- 人工内部沟通的长期事实按来源增量进入原`pdd_knowledge_curation`，不必等整段会话恢复托管；同一来源重复触发不重复提炼，临时库存不进入长期知识。正式发布仍走商品/客服两类知识和原审核、版本事务。
- 能定位的知识纠正携带原引用/版本到候选；审核按原知识ID定位，即使标题变化也不另建冲突知识。UI展示范围和纠正来源，要求人工选择合并或修订，保留原预览CAS。
- 招呼子串不抢走含实质问题的消息；业务JSON校验失败/技术失败不发送默认话术；日志仅记录提示词长度，不记录人工补充和顾客正文。

## 数据迁移与回滚

```sql
ALTER TABLE pdd_conversation_control ADD COLUMN harness_json MEDIUMTEXT NULL;
```

原结构/数据不删改，无新业务表。部署前保留数据库备份与逐文件备份；失败回滚程序，已新增可空列保留，不能删除本轮业务数据。服务器既有主动查询、监听、退避和发送核对政策不变。

## 验证与边界

- 定向worker/恢复/去重/业务测试及前端构建、前端交互回归；后端权限、发送、知识发布与版本回归。
- 本机独立MySQL事务演练：新列、多问题、临时事实不提炼、长期候选增量、执行结果；合成业务数据全部回滚。
- 生产同型号模型、合成上下文验证五类业务案例，不使用真实客户聊天，不调用平台发送。无商品ID时不会伪造商品身份。
- 本地浏览器检查合成会话：AI分页、待补红点、逐问题状态、统一输入、未发送草稿正常显示。
- 上下文256KB、128问题、256事实为本版有界预算，超限明确转人工/报错，不静默丢事实；最近16轮执行摘要用于恢复和诊断，不声称完整业务事件审计。
- 发布与接口检查不等于所有真实顾客案例验收。模型语义判断仍需真实使用验证；没有宣称绝不出错、零平台风险或所有历史消息已经补发。
