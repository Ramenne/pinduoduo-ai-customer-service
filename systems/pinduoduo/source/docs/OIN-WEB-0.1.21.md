# OIN Web 0.1.21 工作基线

基于0.1.20（5d085c6运行、83b25ad记录）。用户授权开发并统一上线图片转人工、长会话压缩、早期回答溯源、运行经验与运营监控。依据交接资料《Harness上下文压缩与运行经验库-讨论结论及实施建议-20261023.md》。

## 本轮完成线

1. 图片/视频通过原收件去重和聊天存档，原会话控制持久接管、原待补/红点提示；人工可查看并补充/回复，明确恢复自动。没有图片识别或新增平台轮询。
2. 已解决问题、非当前事实及结束人工批次先精确归档再从热状态移出；后台持久任务生成有来源摘要。所有模型入口按对象/问题检索摘要并补读原始证据；未完成事项不由模型删改。重启、失败和旧任务不得丢数据/扩大授权。
3. 每个回答持久保留实际正文、知识快照/版本/hash、消息/人工来源、指引/模型版本及原发送账关联；不随16轮热窗口丢失。原窗口可选择回答反馈，也能按最近相关回答解释自然语言纠正。知识内容错误走原知识修订，判断/执行问题进入运行经验。
4. 原AI协作的自然语言纠正及有标识程序异常产生范围明确的经验候选；审核/修订/启用/撤回版本化，现有Harness实际加载相关已启用经验。运营页展示真实连接、待办、待核发送、压缩失败与经验候选，不全量复制聊天或自动改生产代码。

## 不变量与权限

原聊天/收件/发送/接管/正式知识是权威，不新建平行效果账。摘要不能创造新消息、发送授权、送达结果或现时库存。旧发送要求只作为历史。原文、临时事实、未完成问题、纠正与替代关系均保留精确来源。店铺/用户隔离，运行经验先限本店，跨店共享不在本轮授权。知识候选与经验候选都不自动生效。

新增范围明确的归档/摘要与经验表，复用原加法迁移、备份及失败回滚；不删除既有业务数据。用户此前要求不生成中枢任务/工作编号/上传，继续遵守。禁止给真实顾客发送测试消息；合成、真实模型、实际数据库事务与正式环境只读复查分别报告。

## 实施及验收

先把四个入口接到原链，再完成对应存储、恢复和展示，统一验证、统一发布。当前候选不能以建表、文档或测试数量冒充完整可用。重点为超过旧热状态预算的会话→摘要/归档→旧对象追问→重启恢复；知识v1回答→知识v2→纠正仍指向v1；候选经验未生效→审核版本→下一轮实际加载；重复图片推送只有一个持久人工事项。

状态：0.1.21已部署；历史片段定位经补检后由0.1.22接续，详见同目录0.1.22说明。

## 当前实现与接口

- `ContextArchive`保存范围内精确状态、人工批次／段、回答依据和经验版本；`HarnessExperience`保存本店候选与启用状态。原ChatMessage、ConversationControl、收件／发送账和正式知识发布仍为唯一业务权威。
- 业务问题热集合达到48项时，将可移出的已答／已解决项减至32；事实达到96项时，将失效或当前未涉及的事实减至64。未完成问题、其适用事实及全店有效事实不会为凑数被移走；真正活跃集合超预算时保留原输入并交人工。每段最多16项，足量历史才创建摘要任务；短对话不会每来一条就调用总结。
- 人工协作达到40条或约5万字符时，先完整保存较早内容再留下最近16条；未分析贡献继续进入原知识候选任务。结束批次和旧JSON归档可迁入冷层，较大旧批次分段处理。旧发送要求只作为历史资料。以上字符阈值是资源预算，不是模型token容量声明。
- 摘要后台任务复用本地数据库，100秒租约、最多3次尝试，过期可接续；只允许有真实来源ID的逐字摘录，完整原件保留。失败可在运行页重试，不删原文、不改变消息状态、不访问平台。
- 所有模型入口共用的`harness_state.context`优先按对象／数字引用、再按主题词找回原始问题、事实和历史片段；同一稳定ID恢复，当前热状态优先，失效库存不会成为当前库存。来源／边界／会话代际照原链校验。
- 每轮回答保存实际正文、使用过的知识快照与版本、人工／消息来源、规则／模型标识；发送状态展示实时读取原效果账。16轮仅为热窗口，早期依据留在冷层。升级前仅导入仍留存的轮次和确有原账支持的正文，不补造丢失版本。
- AI协作可选中旧回答再自然反馈；旧v1引用随反馈保留，当前v2仍经原候选预览、当前hash与发布事务保护。商品事实／店铺政策继续分别进入原商品／客服知识；理解、检索、执行纠正形成运行经验候选。
- 经验按店铺与当前归属隔离，候选不生效。店铺设置＋客服发送权限可保存、审核启用、修订或撤回；乐观版本校验与不可变历史支持沿用旧内容再审核。已启用且命中关键词的指引实际进入统一模型上下文并随回答记录ID／版本；在途撤回／修订会阻断旧结果应用。经验不授权发送、退款或修改程序。
- 图片／视频进入原收件去重、原聊天存档，创建原持久人工问题与红点；可查看、直接人工回复或描述后与AI继续处理，明确恢复自动。不调用识图模型或新增平台转接接口。
- `GET /chat/workspace/human-history`、`answer-history`为当前会话的冷历史分页；`ai-supplement.answer_id`可选且服务端检查会话范围，不需用户填写ID。`operations`、`experiences`、`experience-versions`、`summaries`为本地状态／版本；`experience-review`、`summary-retry`受店铺设置与原客服权限校验。全部位于现有API前缀下。
- 网页沿用原AI协作窗口，增加回答依据／反馈和更早历史入口；运行状态与经验独立页面`/harness-operations`。页面手动读取本地状态；店铺连接状态取原worker连接登记，未增加平台定时抓取。
