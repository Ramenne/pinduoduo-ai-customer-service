# OIN Web 0.1.19：显式提交、业务引用容错与上下文接续

基线：0.1.18（816cc4e运行，fb65daa阶段记录）。用户报告：AI协作回车误提交；“关联问题不存在”阻塞反馈；工作人员说OK/已发送后仍把昨天已回复的招呼当成新问题。用户确认这不是漏同步报告。

## 根因与修改

- AI共用输入框把Enter绑定为发送，中文选词/换行存在误提交路径。AI入口改为仅发送按钮提交，Enter及组合键不发送；阻止表单隐式提交。顾客输入仍支持Enter发送，IME选词不触发。
- 旧实现把可选related_ids和问题/事实修改目标同样硬校验：一个无法对应的关联编号会回滚整轮有效补充。现在可选关联保留确认部分并记录未确认警示，不据此修改其他问题；新增同轮local_ref由程序分配真实ID后关联。已有问题ID、待补ID和事实来源仍严格隔离；模型先错误定位时自动校正一次，仍错误则保留原始人工输入，不执行错误状态变更或发送，不无限重试。
- 内部协作始终把最后一条顾客消息作为当前user查询，且history_before丢掉它之后的客服外发。现在当前事件是工作人员原文；顾客消息和客服回复一起按实际对话顺序恢复。近期窗口以外，由业务事项来源ID补读原消息；历史读取失败/超预算不得假装空上下文。
- 原OIN ChatStore.ListMasterMessagesAsync按店铺/会话持久保存全部历史；AiReplyOrchestrator的manual_classify检查末尾是否仍为入站，BuildHandoffPrompt区分人工补充与顾客原文。本轮复用这些职责和不变量，继续使用网页原ChatMessage/会话控制记录，不增加第二个消息库。
- 自动分支不再机械移除历史末条：按真实来源消息ID去重，保留客服外发；旧事件已经有更新的顾客消息时只归档，不作为新轮次。人工当前自然语言确认OK不调用模型重新处理旧顾客问题；明确“我已发送”记录为operator_report，不伪造平台发送成功，不重放旧授权。包含新事实的自由表达仍进入模型理解与原知识候选链。
- 已解决问题不删除原聊天/事实，其他未完成事项跨批次保留；关联追问仍可使用源消息与持久业务状态。模型每轮用有界窗口与锚点，不能声称每次全量读取所有聊天。

## 定向验证

- 新增：AI回车/IME/表单按钮；可选关联缺失保留事实、同轮新问题关联、错误修改目标不能关闭别的问题、引用最多校正一次。
- 昨日招呼→已外发回复→今日内部OK/我已发送，不重开顾客招呼；消息边界含客服外发；跨近期窗口原消息仍可读；迟到旧入站不启动新轮次。
- 相关worker、后端发送/工作区回归及前端构建；浏览器合成会话实测两段输入回车保留，未提交。
- 真实模型合成案例：工作人员纠正“昨天已回复，不是新招呼”，输出no_reply、无新对客正文；OK/已回复程序分支不调用模型、不发送顾客消息。
- 对用户截图对应会话做本地记录核对及一次有界单页历史补读，无新增入站；用户随后明确是旧消息误解，不再排查漏同步或增加平台轮询。

## 迁移与边界

无数据库结构变更，复用0.1.18的harness_json及原收发/候选权威，不新增平台轮询或消息通道。修改前备份和原文件摘要冲突检查；失败按本轮文件回滚0.1.18。

人工口语补充不能因内部编号问题被认定无效；有用的经营事实/经验经原候选审核。自主理解、有限校正与线上改程序/发布规则权限不同，不宣称客服能自行改生产代码。
